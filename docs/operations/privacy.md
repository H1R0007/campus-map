# Персональные данные и публичность

Репозиторий публичный, а карта — про реальное здание, где работают и учатся люди. Поэтому часть материалов хранится вне git, а часть обрабатывается до сохранения.

## Что не попадает в репозиторий

| Материал | Где хранится | Почему |
| --- | --- | --- |
| Оригиналы присланных планов | `data-sources/` (локально) | в оригиналах бывает лишнее для публикации: штампы, фамилии, служебные пометки |
| Настоящие фото точек | общая папка, путь в `CAMPUS_PHOTOS_DIR` | на снимках люди и помещения вуза |
| Снимки 360° | `.local/panoramas` или `CAMPUS_PANORAMAS_DIR` | тяжёлые, и на них попадает то же, что на фото |
| Синтетические кампусы для замеров | `.local/campus-*` | генерируются заново |
| Настройки машины | `.env.local` | личные пути |

Все эти каталоги перечислены в `.gitignore`. Строка в `.gitignore` прячет файлы от git, но не защищает от `git add -f`, поэтому правило важнее настройки.

## Фото точек

### Что происходит при добавлении

1. Снимок сжимается.
2. Из файла удаляется место съёмки (EXIF).
3. Снимок ставится прямо.
4. Имя файла — первые 16 знаков SHA-256 содержимого.

Имя по содержимому нужно по технической причине: телефон хранит снимок в кэше и не перепроверяет его, поэтому заменённое фото обязано получить новое имя, иначе на экране останется старое.

### Размытие

Лица, номера машин, таблички с фамилиями размываются до сохранения: в редакторе у фото есть «Размыть…». Рамка протягивается по месту, пиксели размываются сразу, и именно в таком виде снимок видят студенты.

| Свойство | Значение |
| --- | --- |
| Размытие необратимо | восстановить исходное содержимое из сохранённого файла нельзя |
| Рамки сохраняются в данных | поле `blur` — чтобы показать их и повторить размытие при пересжатии |
| Исходный снимок остаётся у фотографа | он вне репозитория, и рамки можно поправить позже |

После сохранения прежнее фото без размытия убирается из общей папки: иначе на диске остаётся копия с лицом.

### Тестовые фото

`data/photos/` содержит только картинки генератора. Если в этом каталоге окажется настоящее фото, `pnpm test` завершится ошибкой с указанием, куда его перенести. Проверка существует потому, что «положу пока сюда, потом перенесу» заканчивается коммитом.

## Что нельзя писать в документацию и данные

| Нельзя | Пример |
| --- | --- |
| настоящие адреса | «ул. Ленина, 5, корпус 3» |
| названия корпусов вуза | «Корпус имени Иванова» |
| фамилии сотрудников | «деканат, каб. 210, Петрова» |
| ссылки на внутренние сервисы | адреса wiki, чатов, файловых хранилищ |
| пути к общим папкам конкретного человека | `D:/Яндекс.Диск/…` в примерах |
| данные из планов, помеченные как служебные | штампы «для служебного пользования» |

Примеры в документации — на тестовом кампусе: «Корпус А», «А-305», «Главный вход».

## Согласие и основания обработки

Проект хранит фотографии помещений и объектов. Решение о том, какие снимки делать и на каком основании их публиковать, принимает вуз: это организационный вопрос, а не технический.

Технически проект даёт три вещи:

- возможность размыть людей и надписи до сохранения;
- хранение фото вне публичного репозитория;
- отсутствие внешних сервисов, которым уходили бы данные пользователей.

## Внешние запросы

Приложение не делает запросов к внешним доменам: нет CDN, веб-шрифтов, карт и аналитики.

Это не только требование изолированной сети. Загрузка файла с чужого домена передаёт третьей стороне IP-адрес посетителя, а для развёртывания в ЕС это отдельное основание обработки, которого у вуза нет.

Проверить сборку на внешние запросы можно так:

```bash
grep -rn "https://" apps/viewer/dist/assets/*.js | head
```

Совпадения в строках вида `http://www.w3.org/2000/svg` — пространства имён XML, а не сетевые запросы.

## Что делать, если персональные данные попали в git

1. Не «исправлять» следующим коммитом: файл остаётся в истории.
2. Удалить файл и переписать историю (`git filter-repo`) либо сделать репозиторий приватным.
3. Если данные уже опубликованы — считать их раскрытыми: удаление из истории не отменяет копий у тех, кто успел их скачать.

Порядок действует и для форков: копия остаётся у форкнувших.

## Проверки в проекте

| Что проверяется | Где |
| --- | --- |
| в `data/photos/` нет настоящих фото | `pnpm test` (сверка с общей папкой) |
| оригиналы планов не попали в сборку | `verify-dist-data.mjs`: лишние файлы в `dist/data` — ошибка |
| фото на точки, на которые ссылаются данные, есть в сборке | там же |
