# Развёртывание и обслуживание

Руководство для ИТ-службы вуза и администратора карты. Технические подробности сборки — в [Сборка и развёртывание](../operations/build-deploy.md); здесь — что и в каком порядке делать.

## Что разворачивается

| Что | Кому | Как |
| --- | --- | --- |
| Навигатор | студентам, сотрудникам, гостям | статические файлы на любом веб-сервере |
| Редактор разметки | команде разметки, не публично | запускается на машине разметчика из репозитория |

Серверной части нет: навигатор — набор файлов, которые отдаёт веб-сервер. Базы данных, фоновых служб и внешних сервисов нет.

## Требования

- **Изолированная сеть поддерживается.** Внешних CDN, шрифтов и карт нет — это требование к сборке, а не пожелание.
- **HTTPS.** Нужен для установки приложения на телефон: без него браузер не даёт установить PWA и отключены часть возможностей.
- **Место на диске.** Сборка навигатора вместе с данными — десятки мегабайт.
- **Ничего не нужно ставить** на сервер: ни Node.js, ни базы данных. Сборка делается на машине разработчика.

## Развёртывание по шагам

### 1. Собрать

На машине с Node 22 и pnpm 9:

```bash
pnpm install
CAMPUS_BASE_PATH=/map/ pnpm build
```

`CAMPUS_BASE_PATH` — путь, по которому сервис будет открываться: `/` для корня домена, `/map/` для подкаталога. Переменная обязательна, если сервис стоит не в корне: без неё карта откроется, а планы и данные — нет.

Результат — каталог `apps/viewer/dist/`, в нём статика вместе с датасетом в `dist/data/`.

### 2. Скопировать

Содержимое `apps/viewer/dist/` — на веб-сервер по выбранному пути.

### 3. Проверить

```bash
node tooling/smoke-test.mjs --app viewer --mode prod --base /map/
```

Проверка открывает сервер и запрашивает файлы по HTTP: главную страницу, датасет, планы, ответы на отсутствующие файлы. Провал означает, что сборка или путь заданы неверно.

Вручную: открыть адрес, найти аудиторию, построить маршрут.

### 4. Обновлять

Повторять шаги 1–3 при изменениях. Новая версия приходит пользователям сама и ждёт согласия: приложение не перезагружается посреди маршрута.

## Обновление данных карты

Данные (`data/`) лежат внутри сборки. Поэтому обновление разметки — это новая сборка.

| Кто меняет | Как |
| --- | --- |
| команда разметки | правит `data/` в редакторе, коммитит, запускает сборку |
| ИТ-служба | получает новую сборку и выкладывает её на сервер |

Отдельной панели администрирования нет: источник истины — файлы в репозитории и git.

## Права и доступ

| Что | Кому |
| --- | --- |
| Навигатор | всем |
| Редактор разметки | только команде разметки, на её машинах |
| Репозиторий | разработчикам; данные карты публичной не должны быть персональными |
| Фото точек | общая папка вне репозитория, доступ у команды разметки |

Редактор в развёрнутом виде писать на сервер не умеет: «Сохранить» доступно только при запуске из репозитория. Развёрнутый редактор отдаёт архив с данными, который разработчик кладёт в репозиторий.

## Что нельзя публиковать

| Материал | Почему |
| --- | --- |
| фото людей и помещений без согласия | персональные данные |
| оригиналы планов из `data-sources/` | в них бывает лишнее для публикации |
| настоящие адреса и фамилии в примерах | репозиторий публичный |

Лица и надписи на фото размываются в редакторе до сохранения. Размытие необратимо.

## Резервные копии

Копировать нужно два места:

| Что | Откуда |
| --- | --- |
| данные карты | каталог `data/` в репозитории (история в git — уже копия) |
| фото точек | общая папка `CAMPUS_PHOTOS_DIR` |

Планы этажей входят в `data/`, поэтому отдельной копии не требуют. Сборка (`dist`) восстанавливается из репозитория одной командой.

## Частые вопросы

| Вопрос | Ответ |
| --- | --- |
| Нужен ли сервер приложений? | Нет, только раздача статических файлов |
| Работает ли без интернета? | Да: приложение и открытые планы кэшируются на устройстве |
| Что будет, если связь пропадёт? | Навигатор продолжит работать с сохранённым; непросмотренные планы будут недоступны |
| Можно ли поставить в подкаталог? | Да, через `CAMPUS_BASE_PATH` при сборке |
| Нужен ли домен с HTTPS? | Для установки на телефон — да |
| Где менять названия аудиторий? | В редакторе, в свойствах точки; затем новая сборка |

## Что делать при сбое

| Симптом | Причина и действие |
| --- | --- |
| Карта открывается, планов нет | сборка без `CAMPUS_BASE_PATH`: пересобрать с правильным путём |
| Данные приходят как HTML | запрос `/data/...` не попал в раздачу данных: проверить, что каталог `data` скопирован внутрь `dist` |
| Нет времени в пути | данные без привязки к метрике: сообщить команде разметки |
| Не устанавливается на телефон | нет HTTPS или манифеста: проверить, что сборка полная |
| После обновления старая карта | приложение ждёт согласия: нажать «Обновить» в сообщении |

Полный список технических проблем — в [Сборка и развёртывание](../operations/build-deploy.md#частые-проблемы).
