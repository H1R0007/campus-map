# Устройство ядра

`packages/core` — доменное ядро: формат данных, граф, поиск маршрута, привязка планов к метрике, поиск по названиям. Пакет не зависит от React, Leaflet, сети и файловой системы (см. [Зависимости и поток данных](dependencies.md)).

| Каталог | Что внутри |
| --- | --- |
| `types/` | контракт формата данных: `MapNode`, `Transition`, `Dataset`, `PlaceKind`, результаты поиска |
| `dataset/` | загрузка и нормализация датасета, раскладка путей, HTTP-источник |
| `graph/` | `Graph` и проверка связности |
| `pathfinding/` | A*, модель стоимости, альтернативные маршруты |
| `projection.ts` | перевод пикселей планов в пространство кампуса |
| `aliases/` | нечёткий поиск по названиям |
| `turns.ts` | повороты у ориентиров |
| `panoramas/` | панорамы 360°: формат, стрелки, привязка к маршруту |
| `geometry.ts` | расстояние, канонический ключ ребра, ключ «корпус + этаж» |

## Граф

`Graph` — единственная структура, по которой ходят поиск, слои карты и проверки. Собирается из нормализованного датасета:

```ts
const graph = Graph.fromDataset(dataset);
```

Либо напрямую из узлов, переходов и привязки:

```ts
const graph = new Graph(nodes, transitions, projection);
```

Все индексы создаются в конструкторе один раз:

| Индекс | Содержимое | Кто использует |
| --- | --- | --- |
| `nodes` | `id → узел` | `getNode`, `hasNode`, `getAllNodes` |
| `nodesByFloor` | `«корпус#этаж» → узлы` | `getNodesForFloor` — слой этажа на каждой перерисовке |
| `transitionsByKey` | канонический ключ ребра → переход | `getTransitionType` — тип шага маршрута |
| `adjacency` | `id → соседи`: рёбра этажа плюс переходы, без дублей и без несуществующих узлов | `getNeighbors` — вызывается на каждом раскрытии A* |
| `world` | `id → точка в метрах` | `getWorld`, только в метрическом режиме |

Что делает конструктор, кроме заполнения индексов:

- переходы дедуплицируются по каноническому ключу ребра: повторная запись `a ↔ b` в любом порядке концов игнорируется;
- переход добавляется в список смежности с обеих сторон, потому что рёбра ненаправленные;
- из списка соседей удаляются несуществующие узлы и повторы: битая ссылка в `neighbors` не должна ронять поиск;
- мировые координаты считаются сразу для всех узлов; если хотя бы для одного узла проекции нет, граф становится пиксельным целиком.

### Граф неизменяемый

Мутационного API нет: индексы строятся только в конструкторе. Причина практическая — методы вида `addNode` позволяли изменить содержимое, не обновив `nodesByFloor`, `adjacency` и `world`, после чего поиск работал по одному набору данных, а карта показывала другой.

Редактор хранит собственное изменяемое состояние и собирает новый `Graph` перед каждым поиском пути. Стоимость сборки на целевом объёме (5 корпусов по 11 этажей) не влияет на отзывчивость интерфейса.

Геттеры `getNodesForFloor` и `getNeighbors` возвращают внутренние массивы индекса без копирования — они вызываются на каждой перерисовке. Изменять эти массивы нельзя; тип возвращаемого значения `readonly` ставит запрет на уровне компилятора.

### Метрический режим

`graph.isMetric` истинно, когда привязка полная: у каждого узла есть точка в пространстве кампуса. От этого флага зависят модель стоимости поиска и наличие времени в пути.

`graph.getWorld(id)` отдаёт точку узла в метрах, `undefined` — в пиксельном режиме и для неизвестного узла. Координаты хранятся в графе, а не в узле: пиксели узла меняются при перетаскивании в редакторе, и копия мировых координат на узле устарела бы после первого изменения.

## Область видимости

`ViewScope` описывает «срез» графа, который показан на карте: территория кампуса либо конкретный этаж.

```ts
type ViewScope = { mode: 'campus' } | { mode: 'floor'; buildingId: string; floor: number };
```

| Функция | Назначение |
| --- | --- |
| `isNodeInScope(node, scope)` | принадлежит ли узел срезу; `null` означает «срез не определён» — не виден ни один узел, это безопасное состояние загрузки |
| `scopeOfFloor(buildingId, floor)` | срез по выбору пользователя; неполный выбор трактуется как территория |
| `scopeOfNode(node)` | срез, в котором виден узел — для перехода «Открыть этаж 3» в шагах маршрута |

Проверка живёт в ядре, потому что её используют оба приложения: раньше она была продублирована в слоях точек и маршрута навигатора.

## Связность

`findConnectedComponents(graph)` обходит граф в ширину и возвращает:

```ts
interface ConnectivityResult {
  connected: boolean;        // все узлы в одной компоненте
  components: string[][];    // компоненты в порядке обхода
  isolatedNodeIds: string[]; // узлы вне основной компоненты
}
```

Используется панелью статистики редактора и проверками данных. Сложность линейна по числу узлов и переходов: прежняя реализация в редакторе для каждого узла перебирала весь список переходов, то есть работала квадратично.

Если компонент больше одной, маршрут до узлов вне основной компоненты не строится — в редакторе это видно в «Проверке», в тестах падает тест связности на реальном `data/`.

## Геометрия и ключи

| Функция | Назначение |
| --- | --- |
| `distance(a, b)` | евклидово расстояние в пикселях; имеет смысл только для точек одного плана |
| `edgeKey(a, b)` | канонический ключ ненаправленного ребра: порядок аргументов не влияет |
| `floorKey(building, floor)` | ключ индекса «корпус + этаж» |

`distance` не используется как эвристика поиска: между этажами пиксели несравнимы. Эвристика живёт в модели стоимости — см. [Поиск маршрута](pathfinding.md).

## Правила правки

- Новый индекс добавляется в конструктор `Graph` и заполняется там же. Отдельного метода «обновить индекс» не появляется.
- Правило принадлежности узла срезу меняется в `scope.ts`, а не в компонентах карты.
- Работа с рёбрами идёт через `edgeKey`: сравнивать пары узлов напрямую (`a === from && b === to`) нельзя, рёбра ненаправленные.
- Проверка связности — только через `findConnectedComponents`: своя реализация в приложении разойдётся с ядром в трактовке изолированных узлов.
