# Устройство навигатора

`apps/viewer` — одностраничное приложение на React. Данные читаются один раз при открытии, дальше всё считается в браузере: граф, поиск маршрута и пошаговые инструкции приходят из `@campus-map/core`.

## Состояние

Шесть хранилищ Zustand, у каждого своя область:

| Хранилище | Что держит |
| --- | --- |
| `mapStore` | загруженные данные, выбранный этаж, выбранная точка, просьба перевести камеру, слои холста |
| `routeStore` | концы маршрута, найденный маршрут, шаг навигации, ограничения, прибытие |
| `settingsStore` | язык интерфейса, тема |
| `recentStore` | недавние места |
| `uiStore` | видимость панелей и диалогов |
| `updateStore` | ожидающая версия service worker |

`mapStore` держит загруженный датасет целиком и подменяет его атомарно:

```ts
interface MapData {
  graph: Graph;
  aliasManager: AliasManager;
  campusMeta: CampusMeta;
  buildingMetas: Map<string, BuildingMeta>;
  placeKinds: readonly PlaceKind[];
}
```

Пять отдельных сеттеров заставляли компоненты перерисовываться на каждом шаге загрузки и допускали состояние, в котором граф уже новый, а метаданные корпусов ещё старые. Признак «данные готовы» — `graph !== null`; отдельного поля `isLoaded` нет, потому что дубль того, что видно по самим данным, рано или поздно расходится с ними.

Выбранный этаж — единственный источник истины о том, что показано на карте: `null` означает территорию кампуса.

## Карта

`CampusMap` выбирает один из двух видов:

| Состояние данных | Что показывается |
| --- | --- |
| привязка полная (`graph.isMetric`) | холст кампуса `WorldCanvas`: территория и этажи всех корпусов на одной карте в метрах |
| привязки нет | `PixelMap` с планом территории или плана выбранного этажа |

Слои у обоих видов одни и те же, потому что они узнают видимое из `useMapView`:

| Слой | Что рисует |
| --- | --- |
| `PlaceLayer` | выбранное место и его карточка |
| `PathLayer` | найденный маршрут, участки на невидимых этажах — пунктиром |
| `PortalLayer` | узлы переходов со значками лестницы, лифта, входа, моста |
| `MarkerLayer` | точки, доступные для выбора |
| `LandmarkLayer` | ориентиры |
| `KindPlacesLayer` | все места выбранного вида, когда цель — «ближайшая столовая» |
| `MapRail` | боковые кнопки приближения и возврата |

Вся обвязка Leaflet — определение размера плана, границы, подгонка вида, смена плана на живой карте — живёт в `packages/mapkit`, а не в навигаторе: раньше она была скопирована сюда из редактора.

### Камера

Перевод камеры — отдельная просьба, а не следствие выбранного этажа:

```ts
interface ViewRequest {
  seq: number;                                  // отличает повторную просьбу о том же виде
  target: { kind: 'campus' } | { kind: 'building'; buildingId } | { kind: 'node'; nodeId };
}
```

`seq` нужен потому, что «покажи корпус А» после того, как человек увёл карту сам, — это новое действие, хотя цель та же. Без счётчика повторная просьба не отличалась бы от прежней и камера не двигалась бы.

На холсте корпус открывается приближением: вместо крыши проявляется этаж, маршрут идёт одной линией с территории в здание.

## Маршрут

`routeStore` хранит концы маршрута как id узлов, а не как текст в полях ввода: имя на языке интерфейса выводится из узла при отрисовке, поэтому смена языка переименовывает точки сама. Раньше в сторе лежал введённый текст, и после смены языка он оставался на прежнем.

Состояние, которое нельзя вычислить из данных, но которое принадлежит маршруту:

| Поле | Смысл |
| --- | --- |
| `stepIndex` | шаг пошаговой навигации; `null` — обзор маршрута |
| `arrived` | человек прошёл последний шаг и нажал «Готово» |
| `nearestKind` | вид места, к ближайшему из которых вела быстрая кнопка |

Все три сбрасываются при пересчёте маршрута: шаг номер 3 прежнего маршрута относится к другому месту.

Поиск вызывается из стора напрямую (`findPath`), ограничения передаются как `PathfindingOptions` — см. [Поиск маршрута](../architecture/pathfinding.md). Если путь не найден, интерфейс показывает текст по коду `reason`, а не сообщение из ядра: ядро пишет пояснения по-русски для разработчика.

## Шаги маршрута

`utils/routeInstructions.ts` превращает найденный путь в список шагов на языке интерфейса:

```ts
interface RouteStep {
  kind: 'start' | 'walk' | 'landmark' | 'transition' | 'arrive';
  title: string;                  // действие: «Поднимитесь на лифте»
  place: string;                  // где: «Этаж 3», «Корпус Б, этаж 2»
  transition: TransitionType | null;
  turn: TurnDirection | null;
  nodeId: string;                 // точка, к которой ведёт шаг
}
```

Действие и место разделены намеренно: имя из данных стоит в именительном падеже, и подставить его в фразу «поверните к …» нельзя ни в одном языке. Действие составляет приложение, место берётся из данных как есть.

Поворот («налево», «направо») считается по линии маршрута в `turns.ts` ядра, а не берётся из поля ориентира. Исключение — `turns` у ориентира, где линия даёт не то направление, которое видит человек.

Цепочка переходов сворачивается в один шаг: «Поднимитесь на лифте — Этаж 5», а не пять одинаковых шагов.

## Язык

| Что | Где |
| --- | --- |
| Список языков, самоназвания, язык данных | `i18n/languages.ts` |
| Словари | `i18n/ru.ts`, `i18n/en.ts` |
| Выбор языка | `settingsStore`: `?lang=` в адресе, затем сохранённый выбор, затем языки браузера |

Порядок выбора: язык из ссылки важнее сохранённого, сохранённый — важнее языка браузера. Ссылка с `?lang=en` нужна для табличек и QR-кодов на английском.

Словарь без всех ключей не компилируется: тип `Messages` требует полного набора, поэтому забытая строка — ошибка сборки, а не пустое место в интерфейсе.

Язык документа (`document.documentElement.lang`) следует за языком интерфейса: по нему экранный диктор выбирает произношение, а браузер — переносы.

## Что меняется при правке интерфейса

- Новая строка — оба словаря: `ru.ts` и `en.ts`. Второй не даст забыть.
- Новый язык — код в `LANGUAGES` и словарь; тип потребует все ключи.
- Изменение текста кнопки или подписи проверяют сценарии в браузере: они ищут элементы по тексту (`tooling/browser/scenarios`).
- Новый слой карты добавляется в `CampusMap` и получает видимое из `useMapView`, а не из своего состояния.
