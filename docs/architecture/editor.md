# Устройство редактора

`apps/editor` — рабочее место команды разметки: загрузить присланные планы, расставить точки, связать этажи, разместить корпуса на территории, проверить и сохранить в `data/`.

Код общий с навигатором только в двух пакетах — `packages/core` и `packages/mapkit`. Приложения друг о друге не знают.

## Три рабочих места

| Рабочее место | Для чего |
| --- | --- |
| `plans` | планы и корпуса: импорт файлов, добавление и удаление этажей, размещение на территории |
| `markup` | разметка: точки, связи, переходы, свойства точки |
| `check` | проверки: «Готовность», «Замечания», «Маршрут» |

Переключение в `markup` сбрасывает выбранный инструмент на «Выделение», если он был не он: инструмент разметки в другом рабочем месте ничего не делает. Выбор точки при переходе в `plans` снимается.

## Стор из срезов

Состояние редактора — одно хранилище Zustand (`immer` поверх всего стора), разрезанное на срезы по темам. Действие среза видит весь стор и может писать в любую его часть: загрузка датасета сбрасывает и выделение, и начатые инструменты.

| Срез | Состояние и действия |
| --- | --- |
| `dataSlice` | данные кампуса, которые правит редактор, и выборки из них |
| `viewSlice` | открытый план, камера, этаж, который открывается при выборе корпуса |
| `windowSlice` | план на карте: корпус и этаж, `building: null` — территория |
| `selectionSlice` | выбранные точки, ребро или переход под курсором |
| `toolSlice` | выбранный инструмент и то, что он успел начать: первый узел ребра, точки линии |
| `editSlice` | правка графа: перемещение, связи, удаление, вставка |
| `kindSlice` | постановка по видам: кисть вида, лестница или лифт на всех этажах, ряд точек |
| `clipboardSlice` | копирование и вставка точек с их названиями |
| `structureSlice` | корпуса, этажи и планы: добавить, изменить, удалить |
| `placeSlice` | постановка корпуса на территорию и масштаб территории |
| `alignSlice` | совмещение точек с новым планом |
| `historySlice` | отмена, повтор, признак несохранённых правок |
| `storageSlice` | сохранение в `data/`, архив, черновик несохранённого |
| `panelSlice` | рабочие места, панели, контекстное меню, диалоги |
| `routeSlice` | симулятор: проложить маршрут, не вставая с места |

Срез — состояние одной темы и действия над ним. Всё это раньше лежало одним файлом на 2200 строк, где правка одной темы требовала понимать остальные.

## История действий

Отмена и повтор — не «откат состояния», а список записей, каждая из которых знает, как отменить и как повторить действие.

```ts
interface HistoryEntry {
  kind: 'node' | 'transition' | 'structure' | 'batch' | …;
  undo: () => void;
  redo: () => void;
}
```

Нагрузки типизированы исчерпывающим объединением с дискриминантом. Раньше они хранились как `unknown`, и обе ветки разбирали их через `as any` — семнадцать приведений, из-за которых опечатка в имени поля обнаруживалась только в браузере, уже сломав отмену.

Что попадает в одну запись:

| Действие | Одна запись |
| --- | --- |
| Постановка кистью (точка с названием, связью и видом места) | да |
| Лестница или лифт на всех этажах корпуса | да |
| Удаление нескольких точек с их названиями и переходами | да |
| Перемещение нескольких точек | да |
| Правка структуры: этаж или корпус целиком, с планом и точками | да |

Соседние сдвиги стрелками сливаются в одну запись, если идут подряд быстрее заданного порога: иначе перемещение на десять пикселей давало бы десять шагов отмены.

Удаление этажа или корпуса возвращает и метаданные, и точки с их названиями, переводами и переходами, и план. Поэтому интерфейс перед удалением показывает, что именно уйдёт (`deletionImpact`): это самая дорогая ошибка разметки.

## Сохранение

| Способ | Когда | Что происходит |
| --- | --- | --- |
| Прямо в `data/` | редактор запущен из репозитория (`pnpm dev`) | «Сохранить» пишет изменившиеся файлы; правки сразу видит навигатор, забирает git |
| Архив | развёрнутый редактор, где записи на диск нет | «Скачать архив», содержимое распаковывается в корень репозитория |
| Учебная копия | пробные действия | всё пишется в копию, настоящий `data/` не меняется |
| Черновик | до сохранения | несохранённые правки держатся в браузере: закрытая вкладка не теряет работу |

Запись идёт через Vite-плагин `tooling/vite-plugin-campus-data.mjs`, тот же, что раздаёт данные в dev-режиме.

## Импорт планов

Мастерская листов принимает PDF, картинки, TIFF, SVG, DXF и ZIP. Подробно — [Мастерская листов](sheets.md).

## Связь с навигатором

Редактор и навигатор не импортируют друг друга. Общее у них:

- формат данных — правки редактора навигатор читает как обычный датасет;
- ядро: граф, поиск, привязка, проверка связности;
- `mapkit`: обвязка Leaflet-карты;
- `readiness` считает, чего не хватает навигатору, а не редактору.

## Правила правки

- Новое действие редактора — срез в `stores/editor/`, член `HistoryEntry`, тест в `tests/history.test.ts`. Действие без записи истории отменяться не будет.
- Правило «что уйдёт при удалении» — в `deletionImpact`, а не в диалоге.
- Проверка данных для интерфейса живёт в `utils/validateData.ts`; ядро отдаёт только `warnings`.
- Новое окно регистрируется в `windowSlice` и рисуется через `DialogLayer`.
