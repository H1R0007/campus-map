# Мастерская листов

Присланные планы приходят файлами: PDF из проектного института, сканы, DXF из AutoCAD, TIFF из архива, иногда всё это в ZIP. Мастерская листов превращает их в планы датасета и не требует расставлять точки по чужой картинке «на глаз».

## Что читается

| Формат | Как читается | Что получается |
| --- | --- | --- |
| PDF | pdf.js, постранично | PNG длинной стороной 4000 точек |
| PNG, JPG, WebP | как изображение | без поворота и обрезки — байт в байт; иначе пересохранение |
| TIFF | UTIF, постранично; однокрасочный чертёж | PNG; скан или фото — JPG |
| SVG | как вектор | остаётся вектором, поворот и обрезка — обёрткой |
| DXF | разбор сущностей | векторный SVG, длинная сторона 3000 точек |
| ZIP | раскрывается в свои файлы | каждый файл — отдельный лист |

DWG не читается: нужен тот же чертёж в PDF или DXF.

Тяжёлые библиотеки — pdf.js, UTIF, разбор DXF, JSZip — загружаются при первом файле своего формата, а не при открытии редактора.

## Лист и кусок листа

Лист — одна страница или один файл. План из листа — не одно и то же: на одном листе бывает два этажа, и человек решает не «что это за файл», а «что это за область».

Поэтому в модели две сущности:

- `ImportSheet` — лист целиком: имя, размер в своих единицах (пункты PDF, пиксели картинки, единицы чертежа), подписи, возможность нарисовать любую область в любом масштабе;
- `Piece` — кусок листа с решением: этаж корпуса, территория или «пропустить».

Из одного листа получается несколько кусков — «ещё область на этом листе».

## Догадки

Для каждого листа редактор предлагает корпус и этаж, а рядом показывает, откуда догадка взялась:

| Источник | Надёжность | Пример |
| --- | --- | --- |
| заголовок листа | высокая | «Корпус А. План 2-го этажа» |
| текст листа, включая номера помещений | средняя | «А-201»: буква корпуса и первая цифра этажа |
| имя файла | низкая | `korpus-B-etazh-2.png` |

Латинские буквы в именах файлов сопоставляются с кириллическими: `V` → `В`. Файлы технических планов иногда названы адресом со строением, без буквы корпуса; такие листы тоже распознаются.

Догадка — предложение, а не решение: человек видит, чему верить, и правит. Лист, который планом не является (экспликация, титул), помечается «пропустить».

## Обрезка, поворот, контур

| Действие | Зачем |
| --- | --- |
| поворот на 90° | лист отсканирован поперёк |
| обрезка области | на листе штамп, рамка, соседний план |
| контур здания | всё за контуром — прозрачно: план ложится на территорию без прямоугольной подложки |
| стирание штампов | у PDF по координатам надписей |

Контур ищется автоматически по линиям чертежа и правится вручную узлами (`OutlineEditor`). Наложение контура на присланный план — отдельная задача: `overlay/` ищет силуэт здания и совмещает его с тем, что уже размечено.

## Масштаб

Масштаб нужен для двух вещей: размер плана в пикселях и метры местности на пиксель.

| Источник | Что даёт |
| --- | --- |
| знаменатель чертежа («1:200») | метры местности на единицу листа |
| единицы DXF | метры или миллиметры по заголовку файла |
| размер TIFF | метры на пиксель из плотности сканирования |
| точки PDF | постоянный коэффициент |

Если масштаб неизвестен, план всё равно импортируется; привязку к метрике задают отдельно — вручную или измерением на территории (см. [Привязка к метрике](../data/placement.md)).

## Запись об исходнике

Каждый план получает поле `source`:

```json
{
  "source": {
    "file": "Корпус А.pdf",
    "page": 2,
    "pageSize": { "width": 1684, "height": 1191 },
    "rotation": 90,
    "crop": { "x": 120, "y": 80, "width": 1400, "height": 900 },
    "outline": [[120, 80], [1500, 80], [1500, 980]]
  }
}
```

По этому полю редактор переделывает план из оригинала и пересчитывает точки разметки вместе с ним. Навигатор поле не читает. Оригиналы складываются в `data-sources/` — каталог вне git.

## Совмещение точек с новым планом

План этажа заменили, точки остались в прежних координатах — у нового плана другой масштаб и сдвиг. Человек называет пары: «эта точка должна стоять вот здесь». Двух пар хватает, чтобы пересчитать все точки плана одним подобием: сдвиг, поворот, масштаб. Третья и следующие пары уточняют и показывают расхождение — где ошибся человек или исказился скан.

## Где это в коде

| Что | Где |
| --- | --- |
| Чтение файлов в листы | `apps/editor/src/import/readers.ts` |
| Догадки о корпусе и этаже | `apps/editor/src/import/guess.ts` |
| Обрезка, поворот, геометрия страницы | `planGeometry.ts`, `trim.ts` |
| Вектор: SVG и DXF | `vector.ts` |
| Масштаб | `scale.ts` |
| Контур здания | `outline.ts`, `outlineEdit.ts` |
| Готовый план из куска листа | `output.ts` |
| Модель решений по листам | `importModel.ts` |
| Окно мастерской | `components/UI/ImportDialog.tsx`, `SheetCanvas.tsx`, `SheetTools.tsx` |
| Наложение на план | `apps/editor/src/overlay/` |

Сценарии в браузере покрывают импорт, обрезку, контур и совмещение точек: `editorImport`, `editorOutline`, `editorSheetTools`, `editorSheetHelp`, `editorAlign`.
