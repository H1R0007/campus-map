# Новое отменяемое действие

Действие, которое меняет данные, обязано отменяться. В редакторе это значит: срез стора, запись в историю и тест. Действие без записи истории выглядит рабочим, но `Ctrl+Z` его не вернёт — а замечают это уже после того, как правку потеряли.

## Порядок работы

### 1. Где живёт действие

| Тема действия | Срез |
| --- | --- |
| точки, связи между ними | `editSlice` |
| постановка кистью, лестница, ряд точек | `kindSlice` |
| корпуса, этажи, планы | `structureSlice` |
| корпуса на территории, масштаб | `placeSlice` |
| виды мест | `kindSlice` |
| копирование и вставка | `clipboardSlice` |

Срез — состояние одной темы и действия над ним. Действие среза видит весь стор через `get()` и пишет через `set` (immer поверх стора).

### 2. Запись в историю

Перед изменением данных собирается всё, что понадобится для возврата, и кладётся в историю одной записью:

```ts
const before = node.neighbors;
set((s) => { /* изменение */ });
historyPush({ kind: 'node', undo: () => …, redo: () => … });
```

Правила:

- **Одна постановка — одна запись.** Лестница на всех этажах, ряд точек, вставка нескольких точек — одна запись, а не по одной на каждый элемент.
- **Слепок, а не ссылка.** То, что возвращается, копируется до изменения: ссылка на массив соседей после правки укажет на изменённое.
- **Возвращается всё, что ушло.** Удаление точки уносит её названия, переводы, вид места и переходы; отмена возвращает их все (`AliasSnapshot`).
- **Составное действие** получает член `BATCH` с полем `kind`: `line`, `deleteMultiple`, `moveMultiple`, `chainConnect`, `autofix`.

### 3. Слияние подряд идущих правок

Если действие может повторяться быстро (сдвиг стрелками, перетаскивание), соседние вызовы сливаются в одну запись по времени и по цели. Иначе перемещение на десять пикселей давало бы десять шагов отмены.

Порог задан в `editSlice.ts` и относится к миллисекундам между вызовами.

### 4. Тест

В `apps/editor/tests/history.test.ts`:

1. Выполнить действие.
2. Отменить — данные вернулись к прежнему состоянию, включая названия и переходы.
3. Повторить — данные снова в изменённом состоянии.

Тест обязан проверять не только «точка вернулась», но и связанные сущности: именно они теряются при неполном слепке.

## Что ещё проверить

- **Признак несохранённых правок** (`historySlice`) выставляется автоматически при записи в историю. Действие, которое меняет данные в обход истории, не помечает датасет изменённым, и «Сохранить» может быть неактивно.
- **Сценарий в браузере** — если у действия есть кнопка или горячая клавиша: см. [Сценарий в браузере](browser-scenario.md).
- **Кнопка в интерфейсе** — элемент в `components/UI/`, подпись в обоих словарях не нужна: редактор одноязычный.

## Чего не делать

- Не писать в состояние данных в обход среза: обновление не попадёт в историю и не попадёт в сохранение.
- Не хранить в записи истории ссылки на объекты стора: после правки они изменятся.
- Не добавлять новое действие без теста истории, даже если «оно только вызывает существующее»: составное действие собирает свой слепок.
