# Новая строка интерфейса

Навигатор двуязычный, редактор одноязычный. Правила разные, и это важно: в навигаторе строка без перевода — ошибка сборки, в редакторе строка пишется на месте.

## Навигатор: оба словаря

| Что | Где |
| --- | --- |
| Словари | `apps/viewer/src/i18n/ru.ts` и `en.ts` |
| Тип словаря | `apps/viewer/src/i18n/index.ts` |
| Список языков | `apps/viewer/src/i18n/languages.ts` |

Тип `Messages` выводится из русского словаря, поэтому английский обязан повторить все ключи. Забытая строка — ошибка `pnpm typecheck`, а не пустое место в интерфейсе.

```ts
// ru.ts
export const ru = {
  route: {
    stepsTitle: 'Шаги маршрута',
  },
} as const;

// en.ts — тот же путь ключей, иначе не скомпилируется
export const en: Messages = {
  route: {
    stepsTitle: 'Route steps',
  },
};
```

### Если строка со склонением

Числа на русском склоняются: «1 минута», «2 минуты», «5 минут». Для этого есть `plural.ts`:

```ts
plural(minutes, { one: 'минута', few: 'минуты', many: 'минут' });
```

В английском склонения нет, и форма одна: `{ one: 'minute', other: 'minutes' }`.

### Если строка — про данные

Имена помещений, корпусов и ориентиров в словарь не попадают: они лежат в датасете (`names`, `translations`). Словарь отвечает только за текст интерфейса.

### Новый язык

1. Код в `LANGUAGES` в `i18n/languages.ts`.
2. Самоназвание в `LANGUAGE_NAMES` — на своём языке, а не на языке текущего интерфейса.
3. Словарь с полным набором ключей.
4. Язык данных (`DATA_LANGUAGE`) не меняется: на нём записаны `names` в датасете.

## Сценарии в браузере

Сценарии ищут элементы по доступному имени — `aria-label` или видимому тексту, — а не по классам разметки. Поэтому **переименование строки ломает сценарий**, и это сделано намеренно: так проверяется то, что видит и слышит человек.

Порядок правки:

1. Найти строку в `tooling/browser/scenarios/*.mjs`.
2. Поменять её там же, где поменяли в словаре.
3. Прогнать `pnpm check:browser` — он идёт минуты и требует установленного Chrome или Edge.

```bash
pnpm build
pnpm check:browser -- --app viewer
pnpm check:browser -- --app viewer --only навигация    # только сценарии с этим словом в названии
```

Если строка используется в нескольких сценариях, её стоит вынести в помощники `tooling/browser/viewer.mjs` — там же, где `PANEL` и `SEARCH`.

## Редактор

Редактор одноязычный: строки пишутся на месте, в компоненте. Но у него есть справка (`F1`) и сценарии, которые ищут кнопки по подписи. Поэтому новая кнопка — это:

1. текст в компоненте;
2. запись в справке, если действие неочевидно (`components/UI/HelpDialog.tsx`);
3. правка сценария, если кнопку нажимают в проверке.

## Проверка

```bash
pnpm typecheck        # английский словарь полон
pnpm --filter @campus-map/viewer test
pnpm build && pnpm check:browser
```

Модульные тесты проверяют сами словари: `apps/viewer/tests/i18n.test.ts` следит, чтобы наборы ключей совпадали, а `plural.test.ts` — формы склонения.

## Чего не делать

- Не собирать строку склейкой: «Найдено » + число + « мест» не переводится. Шаблон с подстановкой живёт в словаре целиком.
- Не писать в словарь имена из данных: они переименовываются в датасете, а не в коде.
- Не менять текст кнопки, не поправив сценарий: проверка в браузере упадёт на «нет кнопки».
