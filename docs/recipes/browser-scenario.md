# Сценарий в браузере

Сценарий — проверка того, что видно только при нажатиях: фокус, контекстные меню, приближение, офлайн, темы, контраст. Модульные тесты этого не ловят.

Сценарии живут в `tooling/browser/scenarios/` и запускаются одним инструментом — без Puppeteer и Playwright: они тянут собственный браузер на сотни мегабайт, а сценариям достаточно установленного Chrome или Edge и десятка команд протокола отладки.

## Устройство

Сценарий — модуль с тремя полями:

```js
export default {
  app: 'viewer',                       // 'viewer' или 'editor'
  name: 'навигатор: быстрые кнопки',   // попадает в отчёт и в --only
  async run({ page, base, step, shot }) { … },
};
```

| Что приходит в `run` | Назначение |
| --- | --- |
| `page` | вкладка: `goto`, `eval`, `waitFor`, `key`, `tap`, `dragVertical`, `viewport`, `sleep`, `send` |
| `base` | адрес приложения без завершающего слэша |
| `step(название, fn)` | шаг сценария: в отчёте видно, на каком шаге упало |
| `shot(имя)` | снимок экрана в каталог `--shots` |

Регистрация — в `tooling/browser-check.mjs`, в массиве `SCENARIOS`. Порядок важен: сценарий, останавливающий сервер, идёт последним.

## Как писать

Элемент ищется по доступному имени, а не по классу разметки:

```js
await v.click('Туалет — ближайшее место');       // aria-label или текст кнопки
await page.waitFor(`${PANEL}.textContent.includes('Маршрут ·')`);
```

Помощники навигатора — `tooling/browser/viewer.mjs` (`viewerHelpers`, константы `PANEL`, `SEARCH`), редактора — `tooling/browser/editor.mjs` (`press`, `mode`, `nodeIds`, `nodePoint`, `drag`, `menuPick`, `status` и другие).

Правила:

- **Проверять то, что видит человек.** Заголовок панели, текст кнопки, адрес страницы, а не внутреннее состояние стора.
- **Ждать условие, а не время.** `waitFor` с условием, а не `sleep` «на всякий случай». Исключение — короткий `sleep` после щелчка, он есть внутри помощников.
- **Один шаг — одна мысль.** Название шага пишется так, чтобы по нему в отчёте было понятно, что сломалось.
- **Данные — тестовые.** Сценарий рассчитывает на тестовый `data/`: туалеты на 1 и 2 этажах корпуса А, столовые в А и Б. Если данные пересобрать, проверки придётся поправить.
- **Не зависеть от порядка сценариев.** Каждый открывает приложение заново; состояние браузера между сценариями не общее (профиль каждый раз новый).

## Запуск

```bash
pnpm build                     # сценарии идут по прод-сборке
pnpm check:browser             # все, оба приложения
pnpm check:browser -- --app viewer
pnpm check:browser -- --app editor --only импорт
pnpm check:browser -- --mode dev          # по dev-серверу, быстрее
pnpm check:browser -- --shots .local/shots # сохранить снимки
```

Браузер ищется в обычных местах установки; другой задаётся переменной `CAMPUS_BROWSER`:

```bash
CAMPUS_BROWSER=/opt/pw-browsers/chromium pnpm check:browser
```

## Отладка

| Симптом | Что делать |
| --- | --- |
| «нет кнопки «…»» | кнопки с такой подписью нет или она `disabled`. Проверить текст в интерфейсе: сценарий ищет точное совпадение `aria-label` или текста, затем вхождение |
| Шаг падает на `waitFor` | условие не выполнилось за отведённое время. Повторить с `--shots` и посмотреть снимок |
| Ошибка в `page.problems` | на странице было исключение, `console.error` или неудачная загрузка ресурса: шаг обязан закончиться без них |
| Провал только в CI | язык браузера: у раннера английский, у сценариев русский интерфейс. Инструмент запускает браузер с `--lang=ru-RU` |
| Провал только на старом Chrome | CI гоняет сценарии в свежем Chrome и в закреплённом Chrome 130: расхождение — повод разобраться, а не отключить проверку |

При провале в CI снимки экрана выкладываются артефактом.

## Чего не делать

- Не искать элементы по CSS-классам: перестановка классов сломает проверку, хотя интерфейс не изменился.
- Не проверять реализации: «в сторе стало 3 элемента» — не то, что видит человек.
- Не отключать сценарий, который «иногда падает»: чаще всего это гонка, и лечится она ожиданием условия.
- Не добавлять `sleep` длиннее нескольких сотен миллисекунд: полный прогон идёт минуты, и каждый лишний сон складывается.
