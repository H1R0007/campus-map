# Новое поле в данных

Поле, которое читается, но не записывается при сохранении, исчезает при первом сохранении из редактора. Поэтому у нового поля формата всегда четыре места, и пропуск любого из них обнаруживается не сразу.

## Четыре места

| # | Что | Где |
| --- | --- | --- |
| 1 | Тип | `packages/core/src/types/<сущность>.ts` |
| 2 | Чтение и нормализация | `packages/core/src/dataset/loader.ts` |
| 3 | Запись при сохранении | `apps/editor/src/utils/datasetFiles.ts` |
| 4 | Тест | `packages/core/tests/` и `apps/editor/tests/` |

Первое и третье связаны компилятором: тип `EveryField<T>` в `datasetFiles.ts` требует, чтобы сохранение перечисляло **все** поля типа, включая необязательные. Со `satisfies BuildingMeta` забытое необязательное поле компилировалось бы, а с `EveryField` — нет.

```ts
type EveryField<T> = { [K in keyof Required<T>]: T[K] };
```

## Порядок работы

### 1. Тип

Поле добавляется в тип сущности. Если это поле формата (а не вычисляемое), оно идёт в `…Data`, а не в нормализованный тип:

- `MapNodeData` — то, что лежит в JSON;
- `MapNode` — то, что отдаёт загрузчик, с заполненными `building` и `floor`.

Обязательное поле — без `?`. Необязательное — с `?` и комментарием, почему оно может отсутствовать.

### 2. Чтение

В `loader.ts` поле читается с проверкой типа. Правила для нового поля:

- принимается только настоящий тип: строка `"10"` в числовом поле — ошибка разметки, о ней сообщается;
- битое значение не роняет загрузку: поле отбрасывается, в `warnings` попадает сообщение с файлом, точкой и именем поля;
- нормализация детерминирована и не зависит от порядка ответов.

```ts
const capacity = asOptionalFiniteNumber(raw.capacity);
if (raw.capacity !== undefined && capacity === undefined) {
  warnings.push(`${where}: capacity должно быть числом — поле пропущено`);
}
```

Старые координаты узлов остаются терпимыми к строкам ради совместимости — это исключение, а не образец.

### 3. Запись

В `datasetFiles.ts` поле добавляется в объект, который уходит в файл. Компилятор укажет на пропуск.

Если поле вычисляемое (`isPortal`), в файл оно не пишется: тогда оно помечается в типе как устаревшее или не входит в `…Data`.

### 4. Тест

| Что проверить | Где |
| --- | --- |
| Чтение: поле попадает в нормализованный объект | `packages/core/tests/dataset.*` |
| Чтение: битое значение даёт warning, загрузка продолжается | там же |
| Запись: поле сохраняется и читается обратно | `apps/editor/tests/` |

Тест «сохранить и прочитать обратно» обязателен: он ловит именно тот случай, ради которого существуют четыре места.

## Что ещё проверить

- **Редактор.** Если поле правится человеком, нужны элемент в свойствах и отменяемое действие — см. [Новое отменяемое действие](add-action.md).
- **Документация.** Поле описывается на странице своего формата (`docs/data/*.md`) и, если оно заметное, в [API ядра](../reference/core-api.md).
- **Снимки сценариев.** Если поле видно в интерфейсе, его проверяет сценарий в браузере — см. [Сценарий в браузере](browser-scenario.md).
- **Совместимость.** Старые датасеты без поля должны читаться: поле необязательное и с разумным значением по умолчанию.

## Пример: поле «вместимость» у узла

```ts
// 1. packages/core/src/types/node.ts
export interface MapNodeData {
  id: string;
  x: number;
  y: number;
  /** Вместимость помещения, человек. Необязательное: у коридора её нет. */
  capacity?: number;
}

// 2. packages/core/src/dataset/loader.ts — в normalizeNode
const capacity = asOptionalFiniteNumber(raw.capacity);

// 3. apps/editor/src/utils/datasetFiles.ts — в объекте узла
...(node.capacity === undefined ? {} : { capacity: node.capacity }),
```

Четвёртый пункт — тесты чтения и сохранения. Без третьего пункта поле исчезло бы после первого «Сохранить», и заметить это можно было бы только в навигаторе.
