# Готовность карты

«Проверка → Готовность» в редакторе — пятнадцать проверок данных, по которым видно, чего не хватает навигатору. У каждой проверки есть состояние, пояснение и кнопка перехода к месту исправления: невыполненная строка ведёт туда, где это правится.

Проверки делятся на четыре группы: каркас, разметка, связи и итог.

## Каркас

| Проверка | Обяз. | Что проверяет | Куда ведёт |
| --- | --- | --- | --- |
| У территории есть план | да | `campus/map.<формат>` существует | «Загрузить план…» |
| Масштаб территории задан | да | `metersPerPixel` в `campus/meta.json` | «Измерить масштаб…» |
| У каждого корпуса есть этажи, у каждого этажа — план | да | у корпуса непустой список этажей, у каждого этажа файл плана | «Добавить этажи…», «Загрузить план…» |
| Каждый корпус размещён на территории | да | `placement` корпуса задан: масштаб, сдвиг, поворот | «Разместить…» |
| Высоты этажей заданы | да | `baseElevationMeters` и `floorHeightMeters` либо `elevationMeters` у этажа | «Открыть корпус» |
| Этажи совпадают с этажом входа | нет | лестницы и лифты на планах разных этажей стоят друг над другом | «Совместить…» |

Без плана территории навигатор покажет вместо неё пустое поле, а корпуса будет не на чем разместить. Без масштаба нет метров, а значит, и времени в пути.

## Разметка

| Проверка | Обяз. | Что проверяет | Куда ведёт |
| --- | --- | --- | --- |
| На каждом этаже есть точки | да | у каждого плана есть хотя бы один узел | «Показать» |
| Точки каждого плана — одна сеть | да | узлы плана связаны между собой | «Показать» |
| Помещения названы | нет | у узлов есть алиасы | «Показать» |

Безымянный узел недостижим из поиска, поэтому проверка «Помещения названы» полезна, хотя и не обязательна: коридорные точки называют редко.

## Связи

| Проверка | Обяз. | Что проверяет | Куда ведёт |
| --- | --- | --- | --- |
| Каждый корпус соединён с территорией | да | есть переход `entrance` между узлом территории и входом корпуса | «Добавить вход…» |
| Этажи корпусов соединены | да | у каждого этажа есть переход к соседнему: лестница или лифт | «Добавить лестницу…» |
| Из любого места можно дойти до любого | да | граф связен: одна компонента связности | «Показать» |

Корпус без входа — отдельный остров: маршрут до него не строится. Этаж без лестницы — то же самое для своего этажа.

## Итог

| Проверка | Обяз. | Что проверяет | Куда ведёт |
| --- | --- | --- | --- |
| В данных нет ошибок | да | связи с несуществующими точками, связи в одну сторону, точки на несуществующих этажах | «Открыть список» |
| Маршрут проверен | нет | проложено хотя бы несколько маршрутов в симуляторе | «Проложить маршрут» |
| Всё сохранено | да | нет несохранённых правок | «Сохранить» |

Часть ошибок данных исправляет кнопка «Исправить что можно» в «Замечаниях»: она достраивает обратные связи и убирает ссылки на несуществующие точки.

## Как это устроено

Каждая проверка — элемент `ReadinessItem`:

```ts
interface ReadinessItem {
  id: string;
  group: 'frame' | 'markup' | 'links' | 'result';
  title: string;
  required: boolean;
  state: 'done' | 'todo' | 'blocked';
  status: string;     // «План на месте», «Ошибок: 3»
  hint: string;       // что значит и что делать
  problems: { text: string; button?: ReadinessButton }[];
  button?: ReadinessButton;
}
```

`button` ведёт к месту исправления: открыть план, измерить масштаб, разместить корпус, показать точки, открыть список ошибок. Кнопка есть только у невыполненной проверки.

Порядок работы подсказывает первая невыполненная обязательная строка: редактор считает её следующей задачей. Если обязательных не осталось, подсказывается любая невыполненная.

## Что делать, если проверка не проходит

| Симптом | Причина |
| --- | --- |
| «Масштаб территории задан» не выполняется | `campus/meta.json` без `metersPerPixel`: измерить масштаб на плане территории |
| «Каждый корпус размещён» не выполняется | нет `placement` у корпуса или он неполный |
| «Высоты этажей заданы» не выполняется | нет высоты у корпуса и нет `elevationMeters` у этажа |
| «Точки каждого плана — одна сеть» | на плане есть узлы без связей: соединить или удалить |
| «Из любого места можно дойти до любого» | граф распался на компоненты: посмотреть «Замечания» |
| «В данных нет ошибок» не выполняется после исправления | ошибки в другом плане: список показывает все |

Проверки не заменяют тесты. `pnpm test` проверяет то же на реальном датасете и падает при нарушении связности, а «Готовность» показывает это человеку в процессе работы.
