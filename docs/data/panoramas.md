# Панорамы 360° (`panoramas.json`)

Экскурсии 360° — прототип (`apps/tour-lab`), в продукт он не входит. Данные при этом описаны форматом датасета: снимки привязаны к узлам графа, поэтому по ним можно вести маршрут и рисовать стрелки перехода между снимками.

Описание лежит в `data/panoramas.json`, сами снимки — вне git и вне `data/`: они тяжёлые, и на снимках вуза бывает то, что публиковать нельзя. Хранилище снимков задаёт развёртывание (`CAMPUS_PANORAMAS_DIR`, по умолчанию `.local/panoramas`).

```json
{
  "panoramas": [
    { "node": "a1_hall", "file": "building_a/1/hall.jpg", "heading": 244, "takenAt": "2026-05" }
  ]
}
```

## Поля

| Поле | Обязательно | Значение |
| --- | --- | --- |
| `node` | да | узел графа, в котором стояла камера |
| `file` | да | имя файла относительно корня хранилища: латиница, цифры, `._-`, каталоги через `/`, расширение `jpg`, `jpeg`, `webp` или `png` |
| `heading` | нет | куда смотрит середина снимка: градусы по часовой стрелке от верха плана этажа (0 — вверх, 90 — вправо) |
| `takenAt` | нет | когда снято: `ГГГГ-ММ` или `ГГГГ-ММ-ДД` |
| `links.hide` | нет | узлы соседних панорам, стрелки к которым не показывать |
| `links.headings` | нет | направления стрелок вручную: узел соседней панорамы → градусы |

Имя файла не может содержать `..`, начинаться с `/` или содержать обратные слэши: оно склеивается с адресом хранилища и не должно выходить за его корень.

## Что происходит при разборе

- Файла нет — панорам нет, предупреждений нет: датасет без панорам обычный.
- Запись без `node` или с узлом, которого нет в графе, пропускается с предупреждением: точку удалили или переименовали, а снимок остался.
- Вторая панорама того же узла пропускается: одна точка — один снимок.
- `heading` не число — снимок остаётся, но без направления: стрелки на нём не показываются.
- Битый `takenAt` отбрасывается, снимок остаётся.
- Углы приводятся к диапазону `[0, 360)`.

Битая запись не отключает остальные панорамы: одна опечатка не должна закрывать экскурсию по корпусу.

## Стрелки

Стрелка ведёт к следующему снимку, а не к соседнему узлу графа: точек в коридоре много, снимков — один на 8–12 метров. Поиск идёт от панорамы по рёбрам и переходам кратчайшими путями и останавливается на каждом узле, у которого есть свой снимок. У прямого коридора со снимками A–B–C из A одна стрелка вперёд, к B, а не две.

Направление стрелки берётся из геометрии: разница координат узлов в пространстве кампуса и `heading` текущего снимка. Там, где геометрия направления не даёт — лестница или лифт стоят в одной точке плана на всех этажах, — направление задаётся вручную в `links.headings`. Лишние стрелки убираются через `links.hide`.

## Как добавить панораму

1. Снять снимок и положить файл в хранилище под именем из латиницы и цифр.
2. Добавить запись в `data/panoramas.json`: узел, файл, `heading`.
3. Проверить `heading`: 0 — камера смотрит вверх по плану, 90 — вправо, 180 — вниз, 270 — влево.
4. Для лестниц и лифтов задать `links.headings`, если стрелка смотрит не туда.
5. Запустить `pnpm test`: разбор панорам проверяется на реальном `data/`, предупреждения попадают в вывод.
