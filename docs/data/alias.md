# Алиасы и поиск (`aliases.json`)

Алиас — человекочитаемое название узла. **Это единственный способ найти помещение в навигаторе**: узел без алиаса недостижим из интерфейса, его нельзя выбрать началом или концом маршрута, даже если он есть на карте и связан со всем остальным.

```json
{
  "aliases": [
    { "id": "a1_room101", "names": ["А-101", "Аудитория 101", "101", "Лекционная 101"] }
  ]
}
```

## Поля записи

| Поле | Что значит |
| --- | --- |
| `id` | id узла в `graph.json` (запись без узла — ошибка данных) |
| `names` | все формы названия на языке данных (русском); первая — основная |
| `name` | устаревшее поле раннего формата; загрузчик приводит его к `names` |
| `translations` | имена на других языках: `{ "en": { "names": [...] } }` |
| `category` | вид места — id из каталога `place-kinds.json` |

При переносе официальных данных алиасы обязательны для каждого узла, до которого должен уметь дойти студент.

## Вид места

`category` связывает место с каталогом видов: по нему навигатор ищет ближайшее место нужного вида, рисует значок и показывает быструю кнопку.

```json
{ "id": "b1_canteen", "names": ["Столовая", "Буфет"], "category": "food" }
```

- Вид необязателен и один на место. У обычной аудитории его нет.
- Учитывается только у места с названием: безымянное место навигатору нечем назвать.
- Вида, которого нет в каталоге, загрузчик снимает с предупреждением.
- Вид задаётся в данных, а не угадывается по названию: «Буфет» — еда, а «Раздевалка» бассейна — не гардероб (запись 19).

Подробно каталог видов — на странице [Виды мест](place-kinds.md).

## Одноимённые помещения

Одинаковые названия у разных помещений **допустимы**: «Столовая» есть в каждом корпусе.

Такие помещения обе показываются в подсказках — с корпусом и этажом, — но точным вводом имени не выбираются: `AliasManager.resolve` для неоднозначного имени возвращает `null`, а не один из вариантов. Выбор неверной столовой приводит к неверному маршруту, поэтому интерфейс показывает список.

Если помещение должно находиться набором одного слова, дайте ему уникальный алиас — «Столовая корпуса А». Список конфликтов отдаёт `ambiguousAliases()`.

## Что умеет поиск

Поиск общий у навигатора и редактора; в редакторе он дополнительно понимает id и координаты `100, 200`.

| Что | Пример |
| --- | --- |
| Регистр, пунктуация, лишние пробелы | `а-305`, `А305`, `а 305` находят «А-305» |
| Номер в любом написании | `305` → «А-305» |
| Латинские буквы вместо кириллических | `a-305` → «А-305» |
| Набор в неверной раскладке | `,b,kbjntrf` → «библиотека» |
| Опечатки | одна в слове из 4–5 букв, две до 8, три дальше: «бибилотека» → «Библиотека» |
| Запрос короче четырёх букв | опечатки не прощаются |
| Слова категорий | «столовка», «поесть», «туалет», «wc» — находят все места вида |
| Имя на другом языке | `Library`, `Canteen` — поиск по всем переводам |

Сворачиваются только буквы, совпадающие и видом, и звучанием (`a e k m o t c x`) и «ё» в «е». Латинская `B` остаётся транслитерацией «Б» и в «В» не превращается — иначе номера аудиторий разных корпусов накладывались бы друг на друга.

Словарь разговорных слов живёт в навигаторе (`search.categoryTerms` в `apps/viewer/src/i18n/`), а не в данных. Разговорное имя одного конкретного места — «Спортзал», «Читалка» — это его алиас в `names`.

## Требования к разметке

- **Один узел — одна запись алиаса.** Дубли разбираются при загрузке.
- **Название не склоняется.** Алиас — именительный падеж, как на табличке; фразы вроде «в аудиторию 101» строит интерфейс, а не данные.
- **Перевод необязателен.** Без перевода интерфейс покажет русское имя, а не пустоту. Номер аудитории переводить не нужно — он совпадает с табличкой.
- **Буквы без латинского двойника.** Номер с такой буквой добавляется в английский перевод транслитерацией: «Б-201» → «B-201».
- **Выход не отмечают.** Это вход, заведённый переходом `entrance`.

Проверки, которые это ловят: «Помещения названы» в «Готовности карты» редактора и тест ядра «каждое название ведёт к существующему узлу».
