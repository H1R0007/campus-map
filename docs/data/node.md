# Узел (`graph.json`)

Узел — точка на плане: дверь аудитории, поворот коридора, лестничная площадка, вход в корпус. В интерфейсе редактора она называется **точкой**, в данных и коде — узлом. Одно и то же (запись 58).

Узлы лежат в `graph.json` этажа или территории:

```json
{
  "nodes": [
    {
      "id": "a1_room101",
      "x": 130,
      "y": 250,
      "neighbors": ["a1_corridor_w"],
      "isPortal": false,
      "comment": "геометрия приблизительная, уточнить у коменданта"
    }
  ]
}
```

## Поля

| Поле | Обязательно | Что значит |
| --- | --- | --- |
| `id` | да | уникальный идентификатор узла во всём датасете |
| `x`, `y` | да | координаты в пикселях изображения плана |
| `neighbors` | нет (но без них узел изолирован) | узлы того же этажа, с которыми есть проход |
| `isPortal` | нет | участвует ли узел в переходах; вычисляется, а не задаётся |
| `comment` | нет | рабочая заметка разметчика |
| `landmark` | нет | ориентир у точки |
| `photos` | нет | фото точки |

`building` и `floor` в файле **не пишутся**. Их определяет путь:

- `campus/graph.json` → `building: "CAMPUS"`, `floor: 0`;
- `buildings/building_a/floors/3/graph.json` → `building: "building_a"`, `floor: 3`.

Поля в типе `MapNodeData` помечены как устаревшие и нужны только затем, чтобы загрузчик заметил расхождение и предупредил. Экспорт редактора их не пишет.

## Координаты

`x`, `y` — **пиксели изображения плана**, отсчёт от левого верхнего угла, ось `y` направлена вниз, как на картинке.

Это не деталь реализации, а условие, чтобы разметка не требовала пересчёта: единица карты в mapkit — пиксель, ось `y` вниз (`PLAN_CRS`). Штатный `L.CRS.Simple` направляет ось вверх и рисовал план отражённым — запись 14 в `DECISIONS.md`.

Пиксели **разных** планов между собой не сравнимы: у каждого своя система координат и свой масштаб. Чтобы появились метры и секунды, планы привязываются к территории — см. [Привязка к метрике](/data/placement).

## Связи

`neighbors` — проходы внутри одного этажа. Связь всегда двусторонняя: если `a` указывает на `b`, то и `b` должен указывать на `a`.

Односторонних проходов в кампусе не бывает: маршрут туда нашёлся бы, а обратно нет. Вкладка «Проверка» в редакторе показывает такие связи, «Исправить что можно» достраивает обратную.

Смена этажа или корпуса в `neighbors` не выражается — для неё есть `transitions.json`.

## `isPortal` — следствие, а не отметка

`isPortal: true` стоит ровно у тех узлов, что участвуют в переходах. Разметчик его не выставляет: редактор держит соответствие сам и при загрузке исправляет расхождения с предупреждением.

Зачем поле нужно вообще, если переходы лежат отдельно: навигатор рисует такие узлы отдельным слоем со значком типа перехода (лестница, лифт, вход). Подробнее — [Переходы](/data/transition).

## `comment` — заметка разметчика

Рабочая заметка: «уточнить у коменданта», «дверь закрыта после 18:00», «геометрия приблизительная». На маршрутизацию не влияет и студентам не показывается.

Поле задумано именно под перенос официальных данных: пока план и проходы сверяют с реальностью, спорные места нужно где-то помечать. Правится в свойствах точки, сохраняется в `graph.json`, участвует в отмене действий.

## Ориентир

Заметная вещь у точки, по которой место узнают на ходу: кофейный автомат, турникеты, стенд. Маршрут через такую точку получает свой шаг: «У кофейного автомата поверните налево».

```json
{
  "landmark": {
    "name": "Кофейный автомат",
    "at": "у кофейного автомата",
    "translations": { "en": { "name": "Coffee machine", "at": "at the coffee machine" } },
    "turns": [{ "from": "a1_corridor_1", "to": "a1_stairs", "turn": "left" }]
  }
}
```

- `name` — как ориентир подписан на карте и под фото, именительный падеж.
- `at` — как он звучит в шаге. Произвольное имя в падеж не поставить ни в одном языке, поэтому фразу составляет редактор, а разметчик её видит и правит; навигатор только читает. Без `at` шаг называет действие, а ориентир — отдельно названием.
- Обе строки — до 80 знаков (`MAX_LANDMARK_LENGTH`).
- **«Налево», «направо», «прямо» в данных не пишутся.** Навигатор считает их сам по линии маршрута (`turns.ts`): через одну развилку разные маршруты идут по-разному. `turns` — редкое исключение для мест, где по линии выходит не то, что видит человек (широкий холл, кривой коридор).
- Ориентир ставят на точку коридора, где сходятся проходы.

## Фото точки

Дверь помещения, вход снаружи, сам ориентир. Первое фото — главное: его показывает навигатор.

```json
{
  "photos": [
    { "file": "058073b50f4d348f.png", "width": 1280, "height": 960 }
  ]
}
```

- Имя файла — первые 16 знаков SHA-256 содержимого и формат (`webp`, `jpg`, `png`). Рядом лежит уменьшенная копия `<отпечаток>.small.<формат>`.
- Имя по содержимому — не украшение: телефон хранит фото и не перепроверяет его, поэтому заменённое фото обязано получить новое имя, иначе на экране осталось бы старое.
- Один снимок у двух точек лежит один раз.
- `width`, `height` — размер полного фото: место под него известно до загрузки.
- `source` — исходный снимок в `data-sources/`, только у разработчика: по нему фото пересжимают и заново размывают.
- `blur` — размытые участки в долях фото от левого верхнего угла. Пиксели уже размыты; поле нужно редактору, чтобы показать рамки и повторить размытие при пересжатии. Размытие необратимо.
- Настоящие фото в репозиторий не попадают: `data/photos/` содержит только тестовые картинки генератора, а остальное живёт в общей папке (`CAMPUS_PHOTOS_DIR`). Если в `data/photos/` окажется не тестовая картинка, `pnpm test` упадёт и скажет, куда её перенести.

## Именование узлов

Соглашение, которое соблюдено в данных и по которому удобно искать:

| Область | Шаблон | Примеры |
| --- | --- | --- |
| Территория | `campus_<место>` | `campus_gate`, `campus_square` |
| Этаж | `<корпус><этаж>_<место>` | `a1_room101`, `b2_lab`, `c1_pool` |
| Лестница / лифт | `<корпус><этаж>_stairs`, `_lift` | `a1_stairs`, `a2_lift` |
| Вход | `<корпус><этаж>_entrance` | `a1_entrance`, `a1_entrance_yard` |
| Переход между корпусами | `<корпус><этаж>_bridge` | `a2_bridge`, `b2_bridge` |

Редактор называет новые узлы по этому же соглашению: щелчок кистью «Туалет» на первом этаже корпуса А даёт `a1_toilet`, следующий такой же — `a1_toilet_2`; копия помещения рядом — `a1_room101_2`, вставка на второй этаж — `a2_room101`.

Если id должен быть другим, он правится в свойствах точки в блоке «Служебное»: редактор переносит на новый id связи, переходы, названия и вид места, занятый или неподходящий id не принимает и объясняет почему, а `Ctrl+Z` возвращает прежний. Говорящие id важны: по прежним автоматическим `building_a_1_node_7` нельзя было ни найти узел в данных, ни понять, что он означает — именно так в датасете однажды появился мусорный треугольник из трёх узлов.

## Как это выглядит в типах

```ts
// packages/core/src/types/node.ts
interface MapNode {
  id: string;
  x: number;
  y: number;
  floor: number;      // из пути файла
  building: string;   // из пути файла
  isPortal: boolean;
  neighbors: string[];
  comment?: string;
  landmark?: Landmark;
  photos?: PointPhoto[];
}
```

Тип `MapNodeData` — форма строки JSON; тип `MapNode` — то, что отдаёт загрузчик. Приложение работает со вторым.
