# Привязка к метрике кампуса

Пиксели разных планов между собой не сравнимы: у каждого плана своя система координат и свой масштаб. Пока планы не привязаны к территории, маршрут можно построить, но нельзя сказать, сколько до цели идти.

Привязка переводит пиксели каждого плана в одно пространство — **метры территории кампуса**. На ней основаны время в пути, эвристика поиска и холст кампуса, где этажи расположены в своих местах.

Все поля необязательные. Но режим **один на весь датасет**:

| Режим | Когда | Что получает навигатор |
| --- | --- | --- |
| метрический | привязаны территория **и каждый** этаж | стоимость в секундах, время в пути, холст кампуса |
| пиксельный | во всём остальном | прежняя модель без времени в пути |

Значений по умолчанию нет: забытый масштаб не превращается в «метр на пиксель», а переводит датасет в пиксельный режим. Загрузчик перечисляет в предупреждениях, чего не хватает каждому этажу.

## Поля

| Файл | Поле | Смысл |
| --- | --- | --- |
| `campus/meta.json` | `metersPerPixel` | масштаб плана территории — задаёт пространство кампуса в метрах |
| `buildings/<id>/meta.json` | `placement.metersPerPixel` | масштаб планов корпуса |
| | `placement.originMeters` | где на территории лежит левый верхний угол плана, `{ "x": …, "y": … }` в метрах |
| | `placement.rotationDeg` | поворот плана относительно территории, градусы по часовой стрелке |
| | `placement.baseElevationMeters` | отметка пола **первого** этажа над уровнем территории |
| | `placement.floorHeightMeters` | высота этажа |
| запись в `floors` | `placement` | масштаб, сдвиг или поворот **этого** этажа поверх корпусных |
| | `elevationMeters` | отметка этажа; важнее формулы корпуса |

```json
{
  "id": "building_a",
  "name": "Корпус А",
  "placement": {
    "metersPerPixel": 0.05,
    "originMeters": { "x": 120, "y": 40 },
    "rotationDeg": 15,
    "baseElevationMeters": 0.6,
    "floorHeightMeters": 3.6
  },
  "floors": [{ "floor": -1, "elevationMeters": -3 }, { "floor": 1 }, { "floor": 2 }]
}
```

## Соглашения формата

- Ось `y` и у планов, и у территории направлена **вниз**, как на изображении.
- Поворот идёт **по часовой стрелке** вокруг левого верхнего угла плана.
- Отметка этажа `n` — `baseElevationMeters + (n − 1) · floorHeightMeters`: по номеру, а не по порядку в списке.
- Где номер с высотой не согласуется (нумерация без нулевого этажа, антресоль), нужен `elevationMeters`.
- Привязка — только масштаб, поворот и сдвиг. Скоса и зеркалирования в формате нет; повёрнутый корпус не меняет ответ «налево/направо».

## Как привязка получается

В редакторе, без правки чисел руками:

1. **Территория — «Измерить масштаб…»**: указать два места на плане и расстояние между ними в метрах. Отсюда берётся `metersPerPixel`.
2. **Корпус — «Разместить…»**: план этажа входа ложится поверх территории, его тащат и поворачивают за ручки, затем щелчком прикалывают булавку в углу, который уже совпал, и доворачивают вокруг неё.
3. **Этаж в другом масштабе — «Совместить с этажом входа…»** в свойствах этажа.
4. **Высоты** — в свойствах корпуса; проверяются строкой «Высоты этажей заданы» в «Готовности карты».

Что осталось сделать, показывает «Проверка → Готовность»: строки про план территории, масштаб, размещение корпусов и высоты — обязательные.

## Что меняется, когда привязка полная

- Навигатор переключается с карты одного плана на **холст кампуса**: территория и этажи всех корпусов на одной карте в метрах. Корпус открывается приближением — вместо крыши проявляется этаж; маршрут идёт одной линией с территории в здание, участки на невидимых этажах просвечивают пунктиром (записи 31, 32).
- В карточке маршрута появляется **время в пути**, а у шагов — длина и время участка.
- Стоимость шага считается в секундах: ходьба, подъём по лестнице, поездка на лифте с ожиданием, проход входа. Числа профиля (`WALKING_PROFILE`) — оценки для взрослого пешехода, а не замеры.
- Поиск получает согласованную нижнюю оценку остатка — условие оптимальности A*. Тесты `pathfinding.consistency` и `pathfinding.optimality` проверяют именно это.

## Диагностика

| Симптом | Что смотреть |
| --- | --- |
| В навигаторе нет времени в пути | режим пиксельный: не привязана территория или хотя бы один этаж; список — в предупреждениях загрузчика (консоль навигатора, панель диагностики редактора) |
| Корпус стоит не на месте | `originMeters`, `rotationDeg` корпуса |
| Этажи не совпадают друг с другом | масштаб или сдвиг у отдельного этажа |
| Лестницы этажей не друг над другом | `mapSize`/привязка этажа, проверка «Этажи совпадают с этажом входа» |
| Маршрут есть, но проходит не там, где ожидалось | сравнить `durationSeconds` и `cost`: при «без лестниц» в стоимости есть штраф, время хранится отдельным полем |

Проверить метрический режим, не трогая канонический `data/`, можно на копии: `CAMPUS_DATA_DIR=/абсолютный/путь pnpm dev`.

Причины и история решения — запись 9 в `DECISIONS.md`.
