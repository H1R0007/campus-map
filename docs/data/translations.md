# Переводы названий

Названия помещений, корпусов и ориентиров лежат в данных, а не в словарях интерфейса. Словари отвечают за кнопки и подписи, данные — за имена.

Перевод необязателен: без него интерфейс покажет основное имя, а не пустоту. Поэтому датасет без переводов работает, но остаётся одноязычным.

## Как записывается

```json
{
  "id": "campus_gate",
  "names": ["Главный вход", "Проходная", "Ворота"],
  "translations": {
    "en": { "names": ["Main gate", "Campus entrance"] }
  }
}
```

| Поле | Значение |
| --- | --- |
| `names` | формы имени на языке данных (русском); первая — основная |
| `translations.<код>.names` | формы имени на другом языке; первая — основная для этого языка |

`names` и `translations` — не одно и то же по смыслу: первые попадают в поиск на любом языке интерфейса, вторые показываются, когда интерфейс переключён на этот язык.

## Коды языков

Код — из списка языков интерфейса навигатора (`apps/viewer/src/i18n/languages.ts`): сейчас `ru` и `en`. Язык данных — `ru`, для него перевод не ищется и не нужен.

Перевод на язык, которого нет в списке, загрузчик сохранит, но интерфейс его не покажет: выбирать этот язык нечем. Такой перевод стоит либо удалить, либо добавить язык.

## Правила перевода

- **Переводится смысл, а не буква.** «Проходная» — это «Main gate», а не «Passage».
- **Номер помещения переводится транслитерацией, только если буква не набирается латиницей.** «А-305» — это «A-305», «Б-201» — «B-201». Остальные номера не трогают: они совпадают с табличкой на двери.
- **Перевод не удлиняет название в разы.** Подпись на карте и в списке ограничена по ширине.
- **Названия в данных — именительный падеж.** Фразы вида «поверните к библиотеке» строит интерфейс, а не данные.

## Поиск и перевод

Поиск идёт по всем именам на всех языках независимо от языка интерфейса: человек, набравший `Library` при русском интерфейсе, найдёт библиотеку. Обратное тоже верно: «Библиотека» находится при английском интерфейсе.

Разговорные слова («столовка», «поесть») — отдельно: они живут в словаре видов мест (`searchTerms` в `place-kinds.json`), а не в переводах.

## Когда перевод не нужен

| Случай | Почему |
| --- | --- |
| номер аудитории | совпадает с табличкой, если буква набирается латиницей |
| «Лестница», «Лифт» у переходов | это не алиасы, а типы переходов: подписи берутся из словаря |
| служебные точки без алиаса | их нет в интерфейсе |

## Проверка

| Что | Где |
| --- | --- |
| Перевод ссылается на существующий узел | тест ядра на реальном `data/` |
| Нет пустых переводов | загрузчик пропускает пустой список имён |
| Поиск находит по переводу | `apps/viewer/tests/` — поиск по именам на другом языке |

Новый язык в датасете добавляется вместе с языком интерфейса: сначала код в `LANGUAGES` и словарь, затем `translations` в данных. Обратный порядок даёт переводы, которые никто не увидит.
