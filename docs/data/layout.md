# Раскладка датасета

Датасет — файлы в каталоге `data/` в корне репозитория. Базы данных и сборки нет: приложения читают файлы по HTTP, редактор в режиме разработки пишет в них напрямую.

```text
data/
├── campus/
│   ├── meta.json         список корпусов, размер и масштаб плана территории
│   ├── graph.json        узлы территории кампуса
│   └── map.<формат>      план территории: png, svg, jpg или webp
├── buildings/<building_id>/
│   ├── meta.json         имя корпуса, список этажей, привязка к метрике
│   └── floors/<floor>/
│       ├── graph.json    узлы этажа
│       └── map.<формат>  план этажа
├── transitions.json      переходы между этажами и корпусами
├── aliases.json          названия узлов: то, что находят поиском
├── place-kinds.json      каталог видов мест (кнопки и значки навигатора)
├── panoramas.json        описание панорам 360° (запись 90)
└── photos/               фото точек; в git лежат только тестовые картинки
```

Рядом с `data/`, но вне git:

| Каталог | Содержимое | Почему вне git |
| --- | --- | --- |
| `data-sources/` | присланные оригиналы планов (PDF, сканы, DXF) | в оригиналах бывает то, что не для публикации; в `data/` лежит готовый план |
| общая папка фото | настоящие фото точек, путь в `CAMPUS_PHOTOS_DIR` | фото людей и помещений вуза; папка одна на всех разработчиков |
| `.local/` | снимки 360°, синтетические кампусы для замеров, снимки экрана проверок | генерируется заново |

## Пути собираются в одном месте

Все пути централизованы в `packages/core/src/dataset/paths.ts`: `CAMPUS_META_PATH`, `buildingMetaPath(id)`, `floorGraphPath(id, floor)`, `floorMapPath(id, floor, format)`, `photoPath(file, size)` и URL-хелперы `datasetUrl`, `campusMapUrl`, `floorMapUrl`, `photoUrl`.

**Склеивать `/data/...` строковым шаблоном в приложении нельзя**: опечатка даёт 404 без другого признака, а базовый путь развёртывания может быть подкаталогом. Если нужного хелпера нет, он добавляется туда, а не в компонент.

Постоянные имена:

| Константа | Значение | Смысл |
| --- | --- | --- |
| `DATA_ROOT` | `data` | имя каталога данных |
| `CAMPUS_BUILDING_ID` | `CAMPUS` | «корпус», которому принадлежат узлы территории |
| `CAMPUS_FLOOR` | `0` | номер этажа для территории |
| `PHOTOS_DIR` | `photos` | каталог фото точек |
| `DEFAULT_PLAN_FORMAT` | `png` | формат плана, если поле не задано |

## План: имя файла фиксировано

План территории и каждого этажа — `map.png`, `map.svg`, `map.jpg` или `map.webp`. Формат выбирается полем `planFormat` (`"png"`, `"svg"`, `"jpg"`, `"webp"`) в `campus/meta.json` и в записи этажа в `meta.json` корпуса. Без поля — PNG.

Произвольное имя файла не поддерживается: раньше оно давало 404 без сообщения. У SVG размер плана задают атрибуты `width` и `height` корневого элемента, в тех же единицах, что и координаты узлов.

Необязательное поле `source` рядом записывает, откуда план взялся и как обработан: имя файла в `data-sources/`, страница, размер страницы, поворот, обрезка, а если план вырезан по зданию — контур `outline`. По этому полю редактор переделывает план из оригинала и пересчитывает точки разметки вместе с ним. Навигатор поле не читает.

## Размеры плана

`mapSize` — размер плана в пикселях. Поле необязательное, но нужное:

- у этажа — в записи `floors` в `meta.json` корпуса;
- у территории — в `campus/meta.json` (там же резервное значение `1200 × 800`, если поля нет).

Без `mapSize` карта до загрузки изображения показывает план в резервных габаритах и меняет размер, когда изображение загружено. Пиксельную геометрию карта берёт из самого файла (`useImageSize` в mapkit), поэтому устаревший размер не ломает маршрут — он даёт расхождение до загрузки изображения.

## Кто какие файлы читает

| Файл | Навигатор | Редактор |
| --- | --- | --- |
| `campus/meta.json`, `meta.json` корпусов | да | да |
| `graph.json` этажей и территории | да | да |
| `transitions.json`, `aliases.json` | да | да |
| `place-kinds.json` | да | да |
| `panoramas.json` | пока нет (прототип) | нет |
| `source` у планов | нет | да |

## Ограничения формата

- **Копия `data/` внутри приложений.** Каталог раздаёт плагин; копия в `apps/*/public/data` делает сборку непредсказуемой, ошибку выявляет `pnpm test`.
- **UTF-8 без BOM.** Файлы читаются с учётом возможного BOM, записываются без него (`.editorconfig` задаёт LF и UTF-8).
- **`building` и `floor` узла определяет путь файла**, а не поля в JSON — см. [формат узла](node.md).
- **Алиас — единственный способ найти точку** из интерфейса. Узел без алиаса недостижим: его нельзя выбрать началом или концом маршрута.
- **Данные в `data/` сгенерированы.** Их собирает `tooling/generate-test-data.mjs` из описания кампуса в `tooling/lib/test-campus.mjs`; правка графа вручную перезаписывается следующим запуском генератора.

Далее: [узел](node.md) → [переход](transition.md) → [алиасы](alias.md) → [привязка к метрике](placement.md).
