# Три формы документации

Одни и те же тексты существуют в трёх видах. Источник истины — Markdown в каталоге `docs/`; остальные два вида из него собираются.

| Форма | Где | Для чего |
| --- | --- | --- |
| Markdown | `docs/**/*.md` | Читать и править. Работает на GitHub без сборки и без сервера |
| Сайт | `docs/dist/` | Локальный просмотр: поиск по всем страницам, навигация, переключение темы |
| Один файл | `docs/dist-offline/campus-map-docs.html` | Передача: вузу, подрядчику, в архив проекта, на машину без сети |

Хостинг не обязателен ни для одной формы. Сайт — статические файлы: если его когда-нибудь понадобится открыть наружу, это включение GitHub Pages на готовый каталог, а не сервер, который нужно поддерживать.

## Что читают в первую очередь

На GitHub. Каталог `docs/` открывается как список файлов, а `docs/index.md` — как карта всех страниц с описаниями и порядком чтения. Для правки достаточно браузера: GitHub принимает изменение одного файла и открывает pull request.

Сайт нужен, когда важны поиск и навигация, и когда текст проверяют перед публикацией. Он собирается локально, интернет для работы не нужен.

## Сборка файла

```bash
pnpm docs:build
pnpm docs:export
```

Результат — `docs/dist-offline/campus-map-docs.html`, около 700 КБ. Внутрь попадают стили, блоки кода, таблицы и оглавление; скриптов и внешних запросов в файле нет, поэтому он открывается двойным щелчком в любом браузере, в том числе без интернета.

Проверить, что файл самодостаточен:

```bash
grep -c '<script' docs/dist-offline/campus-map-docs.html
grep -c 'href="/' docs/dist-offline/campus-map-docs.html
```

Обе команды должны вывести `0`.

## Что в файле есть и чего нет

Есть:

- обложка с датой сборки и коммитом — по ним видно, к какой версии кода относится документ;
- оглавление: страницы в том же порядке, что в навигации сайта, и заголовки второго уровня под каждой;
- все страницы целиком, с переходами по оглавлению.

Нет:

- поиска — в одном файле его заменяют оглавление и поиск средствами браузера (`Ctrl+F`);
- переключателя светлой и тёмной темы: файл всегда светлый, потому что его читают и печатают;
- ссылок на страницы, которых нет в файле: такие ссылки превращаются в обычный текст.

Ссылки на внешние сайты остаются рабочими: они требуют интернета, но сам файл — нет.

## PDF

PDF из файла делается средствами браузера: открыть файл, `Печать` → «Сохранить как PDF». Стили печати заданы в `tooling/docs-export.mjs`: формат A4, каждая страница документации начинается с новой страницы, блоки кода и таблицы не разрываются между листами.

Отдельный конвертер не нужен. `pandoc`, `typst` и дистрибутив TeX пришлось бы ставить на каждую машину, где собирают документацию, и каждый из них по-своему переносит таблицы и блоки кода; браузер уже есть там, где документацию читают.

## Как передавать

1. Пересобрать файл: `pnpm docs:build && pnpm docs:export`. Сборка проверяет карту разделов, стиль и ссылки, поэтому файл не уйдёт с битой ссылкой.
2. Проверить обложку: дата и коммит должны совпадать с версией, которую передаёте.
3. Передать файл (`campus-map-docs.html` или PDF из него), а не папку `docs/dist`: папке нужен веб-сервер, иначе стили и переходы между страницами не работают.

Если получателю нужен текст для правок, а не для чтения, ему передаётся архив репозитория или ссылка на каталог `docs/` — собранный файл для правок не годится.
