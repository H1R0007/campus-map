# Документация в виде одного файла

Документация существует в двух формах: сайт и один файл. Сайт нужен, пока документацию правят; файл — когда её передают.

## Когда какая форма

| Форма | Что это | Когда нужна |
| --- | --- | --- |
| Сайт | `docs/dist/` — статические страницы со стилями, поиском и переходами | Работа: правки, ревью, публикация раз в коммит |
| Один файл | `docs/dist-offline/campus-map-docs.html` — все страницы подряд | Передача: вузу, подрядчику, в архив проекта, на машину без сети |

Файл собирается из того же HTML, что и сайт. Это не вторая версия документации: расхождение возможно только тогда, когда файл не пересобирали после правок.

## Сборка файла

```bash
pnpm docs:build
pnpm docs:export
```

Результат — `docs/dist-offline/campus-map-docs.html`, около 300 КБ. Внутрь попадают стили, преформатированные блоки кода, таблицы и оглавление; скриптов и внешних запросов в файле нет, поэтому он открывается двойным щелчком в любом браузере, в том числе без интернета.

Проверить, что в файле нет внешних зависимостей:

```bash
grep -c '<script' docs/dist-offline/campus-map-docs.html
grep -c 'href="/' docs/dist-offline/campus-map-docs.html
```

Обе команды должны вывести `0`.

## Что в файле есть и чего нет

Есть:

- обложка с датой сборки и коммитом — по ним видно, к какой версии кода относится документ;
- оглавление: страницы в том же порядке, что в навигации сайта, и заголовки второго уровня под каждой;
- все страницы целиком, с переходами по оглавлению.

Нет:

- поиска — в одном файле его заменяет оглавление и поиск средствами браузера (`Ctrl+F`);
- переключателя светлой и тёмной темы: файл всегда светлый, потому что его читают и печатают;
- ссылок на страницы, которых нет в файле: такие ссылки превращаются в обычный текст.

Ссылки на внешние сайты остаются рабочими: они требуют интернета, но сам файл — нет.

## PDF

PDF из файла делается средствами браузера: открыть файл, `Печать` → «Сохранить как PDF». Стили печати заданы в `tooling/docs-export.mjs`: формат A4, каждая страница документации начинается с новой страницы, блоки кода и таблицы не разрываются между листами.

Отдельный конвертер не нужен. `pandoc`, `typst` и дистрибутив TeX пришлось бы ставить на каждую машину, где собирают документацию, и каждый из них по-своему переносит таблицы и блоки кода; браузер уже есть там, где документацию читают.

## Как передавать

1. Пересобрать файл: `pnpm docs:build && pnpm docs:export`.
2. Проверить обложку: дата и коммит должны совпадать с версией, которую передаёте.
3. Передать файл (`campus-map-docs.html` или PDF из него), а не папку `docs/dist`: папке нужен веб-сервер, иначе стили и переходы между страницами не работают.

Исходники документации передаются отдельно и остаются в репозитории: `docs/**/*.md`. Если получателю нужен текст для правок, а не для чтения, ему нужен архив репозитория, а не собранный файл.
