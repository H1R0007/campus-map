## Что сделано последним (PR #19)

Ночная сессия: точечные улучшения навигатора без переделок. Снимки «до» и
«после» — в отчёте сессии (ссылку даёт владелец).

- **Запись 76, подписи корпусов.** На общем виде телефона кампус был без
  единой подписи. Название может выйти за край крыши, если не задевает
  соседние названия и чужие корпуса (`utils/roofLabels.ts`); нажатие на
  название открывает корпус.
- **Запись 77, камера.** Место и шаг на мониторе — с этажом вокруг: метры
  (30 и 28) — минимум, показывается до 12 px на метр (`focusSpan`).
- **Запись 78, поиск.** От известного начала у каждой подсказки время в пути.
- «Поделиться местом» в карточке (`?to=`); устаревшая ссылка — понятное
  сообщение и кнопка «Найти место»; «ничего не нашлось» — с подсказкой;
  «Откуда» при 200 % не обрезается; на шаге «Этаж 3 · ~1 мин» одной строкой;
  без пустой полосы в панели на широком экране.
- README: обе задачи CI, Node 20; замер редактора работает на Windows.

## Что дальше

По убыванию пользы:

1. С новыми планами вуза: экспликация (таблица помещений) → виды и названия
   точек; точки по подписям листа (номера по техпаспорту БТИ ≠ номера
   аудиторий — только как подсказка); замер `WALKING_PROFILE` шагами.
2. Навигатор на телефонах вживую (живые люди, не эмулятор); «Здесь неверно»
   из навигатора в очередь правок редактора.
3. Плавность редактора на слабом ноутбуке. Профиль перетаскивания на 13 409
   точках при CPU ×4 (1 октября): выборка точек этажа **не** виновата —
   около 30 мс за всё перетаскивание. Время уходит на то, как Leaflet двигает
   значки (`_setPosition`, ~170 мс), обновление координат в сторе
   (`positions` в `editSlice`, ~150 мс) и отрисовку браузером. Раскладка
   точек по планам пробовалась и вышла хуже: при перетаскивании данные новые
   каждый кадр, и раскладка пересобиралась каждый кадр. Куда смотреть:
   точки плана на canvas вместо SVG-путей, перерисовка только перетаскиваемых.
4. Несколько разметчиков: сейчас сохранение — один человек на одной машине.
5. Удалить тестовый кампус, когда появятся настоящие данные (в git не класть).

## Как проверять

`pnpm build && pnpm typecheck && pnpm lint && pnpm test`, затем
`pnpm check:browser` (23 сценария редактора, 9 навигатора; полный прогон на
ПК владельца — около 12 минут). В облаке браузер —
`CAMPUS_BROWSER=/opt/pw-browsers/chromium`. Сценарии prod-сборки берут `dist`
— после правок пересобрать.

Замер редактора: прод-сборка несёт данные в себе, поэтому большой набор
подставляется при сборке, а после замера сборка возвращается обычной:

```bash
node tooling/generate-synthetic-campus.mjs --out .local/campus-measure --buildings 10 --rooms 60 --metric
CAMPUS_DATA_DIR=<путь к .local/campus-measure> pnpm --filter @campus-map/editor build
node tooling/measure-editor.mjs --data .local/campus-measure --cpu 4 [--profile]
pnpm --filter @campus-map/editor build
```

На Windows браузер — `CAMPUS_BROWSER` с путём к Edge или Chrome.
