## Что сделано последним

**Мастерская листов, этап 3 (запись 82).** «Эта же область — ещё N листам
файла» и «Область как у листа…» — у документа БТИ рамка на листах обычно
одна; проверенные листы не меняются. «Найти контуры на всех листах» — разом,
с «Остановить». Перед поиском контура и обрезкой полей лист очищается
(`import/sheetClean.ts`): рамка листа, а у PDF — штампы и заголовки по
надписям. Поля на PDF обрезаются по зданию. Поиск подкладывает поле бумаги
вокруг картинки — в плотной обрезке зданием больше не становится вся рамка.

**Этапы 1–2 (записи 80–81, PR #20, #22).** Мастерская во весь экран:
приближение колесом, ручки 10 px, своя отмена у листа, Enter — следующий
лист; инструменты V/H/P/R/X/B, «Вырезать» для прилипшего штампа, «Здание
здесь», меню по правой кнопке.

**Экскурсии 360° (запись 90, PR #21, другой чат).** Основа в
`packages/core/src/panoramas/` и прототип `apps/tour-lab` (порт 3002):
панорама — в точке графа, стрелки — к соседним снимкам из графа, снимки — вне
git (`data/panoramas.json` описывает 10 точек тестового кампуса).

**Фото мест и ориентиров (записи 85–89, PR #23, другой чат).** У точки —
ориентир и фото; навигатор говорит «у колонн налево» сам и показывает фото
над текстом шага; в редакторе — «Проверка → Фото» и размытие лиц и надписей.
Фото — вне git, в общей папке.

**PR #19** — навигатор (записи 76–79): подписи корпусов на общем виде,
камера на мониторе, время в подсказках поиска, шторка за пальцем.

3. С новыми планами вуза: экспликация (таблица помещений) → виды и названия
   точек; точки по подписям листа (номера по техпаспорту БТИ ≠ номера
   аудиторий — только как подсказка); замер `WALKING_PROFILE` шагами.
4. Навигатор на телефонах вживую (живые люди, не эмулятор); «Здесь неверно»
   из навигатора в очередь правок редактора.
5. Плавность редактора на слабом ноутбуке. Профиль перетаскивания на 13 409
   точках при CPU ×4 (1 октября): выборка точек этажа **не** виновата —
   около 30 мс за всё перетаскивание. Время уходит на то, как Leaflet двигает
   значки (`_setPosition`, ~170 мс), обновление координат в сторе
   (`positions` в `editSlice`, ~150 мс) и отрисовку браузером. Раскладка
   точек по планам пробовалась и вышла хуже: при перетаскивании данные новые
   каждый кадр, и раскладка пересобиралась каждый кадр. Куда смотреть:
   точки плана на canvas вместо SVG-путей, перерисовка только перетаскиваемых.
6. Несколько разметчиков: сейчас сохранение — один человек на одной машине.
7. Удалить тестовый кампус, когда появятся настоящие данные (в git не класть).

## Как проверять

`pnpm build && pnpm typecheck && pnpm lint && pnpm test`, затем
`pnpm check:browser` (28 сценариев редактора, 10 навигатора; полный прогон на
ПК владельца — около 12 минут). В облаке браузер —
`CAMPUS_BROWSER=/opt/pw-browsers/chromium`. Сценарии prod-сборки берут `dist`
— после правок пересобрать.

Замер редактора: прод-сборка несёт данные в себе, поэтому большой набор
подставляется при сборке, а после замера сборка возвращается обычной:

```bash
node tooling/generate-synthetic-campus.mjs --out .local/campus-measure --buildings 10 --rooms 60 --metric
CAMPUS_DATA_DIR=<путь к .local/campus-measure> pnpm --filter @campus-map/editor build
node tooling/measure-editor.mjs --data .local/campus-measure --cpu 4 [--profile]
pnpm --filter @campus-map/editor build
```

На Windows браузер — `CAMPUS_BROWSER` с путём к Edge или Chrome.
