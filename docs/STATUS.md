## Что сделано последним

**Мастерская листов, этап 2 (запись 81).** Слева от листа — инструменты:
«Выбор» V, «Рука» H, «Контур по точкам» P (Shift ровняет стену), «Прямоугольник»
R, «Вырезать» X (прилипший штамп или заголовок — одним прямоугольником
поперёк перемычки), «Здание здесь» B; правая кнопка — меню у точки листа.
Поиск контура узнаёт рамку листа по полю бумаги внутри неё, а щель (двери)
берёт по масштабу чертежа — заголовок листа больше не прилипает к зданию.
Новые файлы: `import/outlineEdit.ts` (вырез, обводка; библиотека
`polygon-clipping`), `import/traceSheet.ts`, `components/UI/SheetTools.tsx`,
`sheetToolList.ts`; сценарий `editor-sheet-tools.mjs`.

**Этап 1 (запись 80, PR #20).** Мастерская во весь экран: листы с
отметками, приближение колесом с дорисовкой, ручки 10 px, «+» на линии, своя
отмена у листа, Enter — следующий лист.

**PR #19** — улучшения навигатора (записи 76–79): подписи корпусов на общем
виде, камера на мониторе, время в подсказках поиска, шторка за пальцем.

## Что дальше

По убыванию пользы:

1. Мастерская листов, этапы 3–4 (одобрены владельцем). Помощь программы:
   автообрезка, которая не видит рамку листа (на настоящих листах сейчас

   файла» (у листов одного документа рамка обычно одна); контур по стенам.
   Проход на настоящих листах — образцы владельца в `.local/real-plans/`
   (в git не класть); исходный PDF попросить: снимки экрана ~1000 px и без
   масштаба, щель поиска на них — по размеру листа.
2. С новыми планами вуза: экспликация (таблица помещений) → виды и названия
   точек; точки по подписям листа (номера по техпаспорту БТИ ≠ номера
   аудиторий — только как подсказка); замер `WALKING_PROFILE` шагами.
3. Навигатор на телефонах вживую (живые люди, не эмулятор); «Здесь неверно»
   из навигатора в очередь правок редактора.
4. Плавность редактора на слабом ноутбуке. Профиль перетаскивания на 13 409
   точках при CPU ×4 (1 октября): выборка точек этажа **не** виновата —
   около 30 мс за всё перетаскивание. Время уходит на то, как Leaflet двигает
   значки (`_setPosition`, ~170 мс), обновление координат в сторе
   (`positions` в `editSlice`, ~150 мс) и отрисовку браузером. Раскладка
   точек по планам пробовалась и вышла хуже: при перетаскивании данные новые
   каждый кадр, и раскладка пересобиралась каждый кадр. Куда смотреть:
   точки плана на canvas вместо SVG-путей, перерисовка только перетаскиваемых.
5. Несколько разметчиков: сейчас сохранение — один человек на одной машине.
6. Удалить тестовый кампус, когда появятся настоящие данные (в git не класть).

## Как проверять

`pnpm build && pnpm typecheck && pnpm lint && pnpm test`, затем
`pnpm check:browser` (25 сценариев редактора, 9 навигатора; полный прогон на
ПК владельца — около 12 минут). В облаке браузер —
`CAMPUS_BROWSER=/opt/pw-browsers/chromium`. Сценарии prod-сборки берут `dist`
— после правок пересобрать.

Замер редактора: прод-сборка несёт данные в себе, поэтому большой набор
подставляется при сборке, а после замера сборка возвращается обычной:

```bash
node tooling/generate-synthetic-campus.mjs --out .local/campus-measure --buildings 10 --rooms 60 --metric
CAMPUS_DATA_DIR=<путь к .local/campus-measure> pnpm --filter @campus-map/editor build
node tooling/measure-editor.mjs --data .local/campus-measure --cpu 4 [--profile]
pnpm --filter @campus-map/editor build
```

На Windows браузер — `CAMPUS_BROWSER` с путём к Edge или Chrome.
